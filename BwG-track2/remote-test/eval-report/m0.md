## Key finding (P1, Cloud-Shell-specific): DK MCP needs a quota project

On Cloud Shell the try-it (`answer_query`) returns **Forbidden**. Root-caused by
hitting the MCP endpoint directly:

- `initialize` and `tools/list` → **HTTP 200** (endpoint + user ADC token are fine).
- `tools/call answer_query` with **no** `X-Goog-User-Project` → **HTTP 403**:
  _"The developerknowledge.googleapis.com API requires a quota project, which is
  not set by default."_
- Same call **with** `X-Goog-User-Project: gcp-samples-ic0` → **HTTP 200** + answer.

Why it worked on the old Qwiklabs run: that used a **workstation service-account**
identity that carried an implicit quota project. Cloud Shell uses the **ambient
user ADC**, which has **no** quota project — and it can't be set the usual way:

- There is **no** `~/.config/gcloud/application_default_credentials.json` (ambient
  creds), so `gcloud auth application-default set-quota-project` fails with
  _"Application default credentials have not been set up."_
- `GOOGLE_CLOUD_QUOTA_PROJECT` in agy's env did **not** help — agy's
  `google_credentials` provider reads the quota project from the credential file,
  not the env var, and does not send `X-Goog-User-Project` on its own.

**Headless fix that works** (validated this run): add a `headers` entry to the DK
MCP server config so every call carries the quota project:

```json
{
  "mcpServers": {
    "google-developer-knowledge": {
      "serverUrl": "https://developerknowledge.googleapis.com/mcp",
      "authProviderType": "google_credentials",
      "headers": { "X-Goog-User-Project": "<PROJECT_ID>" }
    }
  }
}
```
