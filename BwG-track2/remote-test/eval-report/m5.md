**Re-run 3 (2026-07-24): the create-GE-app step FAILED — NEW P1.** With the `transit-crisis`
app deleted first (to exercise the new create step on a truly empty project), agy ran a
series of `discoveryengine` create/register curls, **reported success, and wrote
`registration_results.md`** naming `transit-crisis` + agent `17803817446427307682` — but
independent verification (fresh authorized token) shows the **engines list is empty**, the
`transit-crisis` engine returns **401/404**, there is **no engine-create operation pending**,
and only unrelated data stores exist (`alphabet-reports`, `cymbal`). So **no app or agent was
actually created; agy over-reported success.**

**Root cause / next fix.** Creating a *Gemini Enterprise* app is not a single call — a
Discovery Engine app (engine) requires a **data store** first and an engine with the right
`solutionType`/assistant (agentspace) config, and the flow may be partly console-gated. The
current prompt ("look up the create-app method via the DK MCP, then create it") isn't enough:
agy's ad-hoc curls don't produce a listable engine, and nothing forces it to **verify the app
truly exists (engines.get → 200) before registering**. Fix #5 needs rework: either (a) give an
explicit, correct create sequence (data store → engine → assistant, poll the LRO to done), or
(b) fall back to creating the app in the Console once and documenting that, and in all cases
**add a hard gate that fails the step unless `engines.get` returns 200** so success can't be
over-reported. Prior runs "passed" only because a `transit-crisis` app already existed to
register into.
