## Findings

- **P1 — The crisis sim (Step 2) hangs because of the code executor + AFC.** After M2
  added `BuiltInCodeExecutor` to the agent that already has 5 function tools, the
  google-genai SDK **disables Automatic Function Calling** (`Tools at indices [1] … AFC is
  disabled`). agy's hand-written `simulate_crisis.py` drove the agent through a path that
  relies on AFC, so tool calls stopped resolving and Scenario 8 (a `set_home_station`
  tool call) hung indefinitely. **Important:** the same agent works fine through **ADK's
  own Runner** — the deployed agent (M2 Step 6), the playground (M1), and **`adk eval`
  (Step 3) all execute tools correctly**, because ADK does manual function-calling and
  doesn't depend on AFC. **Suggest** Step 2 tell the student to drive scenarios via the
  ADK `Runner` (as the prompt intends) rather than a raw-genai/AFC path, and/or add a
  hang guard (per-scenario timeout). On the prior Gemini-3.5 Qwiklabs run this passed
  10/10; the code-executor+AFC interaction is the new failure mode.
- **P1 — Grounding trap fails (Step 3).** With Gemini 3.6 Flash the agent answered the
  "which platform" question rather than declining (no tool provides platform data), so the
  `hallucinations_v1` judge failed that case (3/4). The prior Gemini-3.5 run scored 4/4.
  Worth strengthening the "don't invent / say when you can't know" rule in the system
  instruction, or the eval expectation. This is the eval **doing its job** — the value of
  M4 is exactly catching this.
