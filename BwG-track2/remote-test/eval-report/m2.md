## Findings

- **P1 — Step 3 (code execution) can silently no-op.** On the first run agy read the DK
  MCP but made **no code change** and reported completion in 19 s; `BuiltInCodeExecutor`
  was absent (verified in `agent.py`). A re-run fixed it. Likely cause: adding
  `BuiltInCodeExecutor` alongside 5 function tools on one agent is a non-obvious ADK move,
  and the step's success wording lets agy "complete" without the edit. **Suggest** Step 3
  add an explicit self-check ("confirm `code_executor=BuiltInCodeExecutor()` is set in
  `agent.py` and show a trace where Python actually ran") so a no-op can't pass. Note it
  did coexist with the 5 tools without breaking function calling (smoke + deployed S1–S3
  still worked).
- **P2 — `agysend` premature markers on deployed/background steps (5, 6).** Deployed calls
  have long static waits that trip the stability detector; the step-6 transcript captured
  empty even though agy finished. Ground truth = the Vertex operation + the live pane +
  the memories API. (Harness: use a larger `stable` window, e.g. 40–60 s, for deployed
  steps; the eval used pane + API cross-checks instead.)
